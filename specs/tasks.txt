# [CONCLUÍDO - PR #232] sdd-012-ai-agent-fallback-safety

Débito técnico levantado pela revisão (code-reviewer) do sdd-006-ai-agent-reliability, resultado AJUSTES NECESSARIOS:

1. (Bloqueante) `FallbackAiAgent` (`feature/ai-agent/.../data/service/FallbackAiAgent.kt`) recorre ao
   provider secundário para qualquer exceção do primário, mesmo quando uma tool call já foi
   executada (efeito colateral real, ex. produto já gravado no Firestore) na mesma rodada —
   contradiz o próprio critério de aceitação do sdd-006 ("exceto se o primário já executou uma
   tool nesta rodada"). Risco de duplicar a ação ao cair no secundário. Agora que
   `AiAgentFactoryImpl.selectAgent` sempre envolve `FallbackAiAgent` quando os dois provedores
   existem, esse caminho é o padrão para a maioria dos usuários, não um caso raro.
2. (Bloqueante, documentação) `AiSession.clearHistory()` (novo método público em
   `core/ai/.../contract/AiSession.kt`) não está registrado em nenhum `tasks.md` como mudança de
   contrato público — foi necessário por uma restrição real de classpath (`:feature:chat`/`:app`
   não têm o SDK do Gemini, que `core:ai` só expõe como `implementation`) descoberta durante a
   implementação do sdd-006, mas o SDD daquela tarefa não foi atualizado para refletir isso.
3. (Aviso) `AiSession.history: MutableList<Content>` continua público e mutável mesmo depois de
   `clearHistory()` existir — os dois mecanismos de limpeza coexistem; avaliar se vale estreitar o
   contrato.
4. (Aviso) Faltam testes no nível `sendMessage` completo de `GeminiAiAgent`/`OpenRouterAiAgent`
   para `MAX_TOOL_ROUNDS` (parar na 5ª rodada, nunca mandar a 6ª) e para o relançamento da
   exceção de transporte — não cobertos por não existir hoje infraestrutura de mock do SDK do
   Gemini (`GenerativeModel`/`Chat`, construído via `by lazy`) nem do `HttpClient` do OpenRouter
   (hardcoded, sem injeção).

Referência: revisão completa na conversa que implementou sdd-006 (seção "Divergências
bloqueantes" e "Avisos" do code-reviewer). Nenhum código de produção é alterado nesta tarefa de
planejamento; o plano deve decidir, para o item 1, entre corrigir a lacuna (adicionar uma guarda
de "tool já executada") ou rebaixar/documentar o critério de aceitação do sdd-006 como risco
aceito, com justificativa.

# [CONCLUÍDO - PR #234] sdd-014-ai-agent-three-tier-config

Implementar layout de configuração de agente de IA em 3 níveis no app:
1. Nível 1: Valor default sempre o mesmo (`openrouter/free`, automático e gratuito).
2. Nível 2: Seleção de agente específico (modelos built-in/gratuitos disponíveis).
3. Nível 3: Agentes de IA pagos usando API key externa (Bring Your Own Key - BYOK), permitindo incluir chaves para Claude, GPT e outros com pagamento externo dentro do app.
