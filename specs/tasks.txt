# sdd-025-auditoria-clean-architecture-design-patterns

Auditoria de conformidade com Clean Architecture (grafo de dependências entre os 19 módulos, separação de
camadas dentro de cada feature) e de Design Patterns GoF (já aplicados vs. oportunidades de consolidação),
realizada em 2026-11-02 a pedido do usuário. O projeto já tem um guard-rail Konsist real e passando
(`app/src/test/.../architecture/ArchitectureTest.kt`) cobrindo a Dependency Rule — a dívida real encontrada
não está no grafo de módulos, e sim em: `AgentRegistry` como service locator global no chokepoint de
dispatch de IA (A-01, P1), regra de negócio divergente entre `invoke()`/`execute()` em `ProductSaveUseCase`
(A-02, P1), duplicação de dispatch entre `GeminiAiAgent`/`OpenRouterAiAgent` já excluída do gate de
cobertura do Kover por esse motivo (A-03, P2), e `aiProvider` "stringly-typed" que deve ser resolvido antes
do `sdd-014` (BYOK multi-provider) (A-04, P2).
Plano detalhado em: `specs/sdd-025-auditoria-clean-architecture-design-patterns/tasks.md`.

Roadmap derivado desta auditoria:
1. sdd-026-ai-provider-consolidation: Template Method (`BaseAiAgent`) + `enum AiProvider`, desbloqueia a
   cobertura hoje excluída do Kover. **Deve rodar antes de sdd-014.** Plano pronto em
   `specs/sdd-026-ai-provider-consolidation/tasks.md`, status `ready`.
2. sdd-027-ai-registry-di-refactor: substitui o `object AgentRegistry` por registro via Hilt Multibinding.
   Maior risco — sequenciar depois que `sdd-017` (branch em andamento) estabilizar.
3. sdd-028-business-rule-parity-review: corrige `ProductSaveUseCase` e audita os demais `AgentActionUseCase`
   quanto ao mesmo padrão de regra divergente entre caminho humano e caminho do agente.
4. sdd-029-visibility-and-dependency-cleanup: `internal` em `feature:subscription`/`products`, AD formal
   para `cart`→`products`/`shopping`, remoção de dependência Gradle morta `shopping`→`settings`.

# sdd-013-openrouter-dynamic-models

Carregar dinamicamente a lista de modelos de IA da API do OpenRouter (`https://openrouter.ai/api/v1/models`) em vez da lista fixa (`AiModel.freeModels`), permitindo a seleção de modelos com fallback para a lista estática em caso de falha/offline e mantendo sempre um modelo gratuito (`free`) como padrão.

# sdd-014-ai-agent-three-tier-config

Implementar layout de configuração de agente de IA em 3 níveis no app:
1. Nível 1: Valor default sempre o mesmo (`openrouter/free`, automático e gratuito).
2. Nível 2: Seleção de agente específico (modelos built-in/gratuitos disponíveis).
3. Nível 3: Agentes de IA pagos usando API key externa (Bring Your Own Key - BYOK), permitindo incluir chaves para Claude, GPT e outros com pagamento externo dentro do app.

# sdd-015-chat-bottom-sheet-voice

Converter a tela de chat (`AiChatScreen`) em um ModalBottomSheet (com suporte a navegação em diálogo/bottom sheet no `chatGraph`), contendo:
1. Ícone de fechar à direita.
2. Ícone de histórico à esquerda, abrindo uma lista de conversas anteriores.
3. Texto de boas-vindas: "Como Cestou pode lhe ajudar?".
4. Input de mensagem com botão dinâmico: se houver texto, exibe o ícone de enviar (send); se não houver texto, exibe o ícone de microfone (voice input) para gravação/simulação de transcrição de áudio para texto para envio à IA.
